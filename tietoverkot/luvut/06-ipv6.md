# IPv6

IPv4:n 4,3 miljardia osoitetta loppuivat jo 2010-luvulla, ja NAT on
ollut sen jälkeen pakollinen kiertotie. IPv6:n osoite on 128-bittinen,
joten osoitteita riittää jokaiselle laitteelle ilman muunnoksia.
Merkittävä osa liikenteestä, erityisesti mobiiliverkoissa, kulkee jo
IPv6:lla. Useimmat verkot ovat *kaksipinoisia* (*dual stack*): sama kone
käyttää molempia, ja sovelluksen on toimittava kummalla tahansa.

## Osoitteen esitys

Osoite kirjoitetaan kahdeksana 16-bittisenä heksaryhmänä. Kunkin ryhmän
alun nollat jätetään pois, ja yksi peräkkäisten nollaryhmien jakso
korvataan merkinnällä `::`. Normalisoitu muoto (RFC 5952) on
pienaakkosin, ja `::` korvaa pisimmän jakson:

| Etuliite | Tyyppi | Vastine IPv4:ssä |
|----------|--------|------------------|
| `2000::/3` | maailmanlaajuinen yksittäisosoite (GUA) | julkinen osoite |
| `fc00::/7` (käytössä `fd00::/8`) | yksityinen (ULA) | RFC 1918 |
| `fe80::/10` | linkkipaikallinen, jokaisella liitännällä | `169.254.0.0/16` |
| `ff00::/8` | ryhmälähetys | `224.0.0.0/4` |
| `::1` | silmukka | `127.0.0.1` |
| `2001:db8::/32` | dokumentaatio | `192.0.2.0/24` |

IPv6:ssa ei ole yleislähetystä: sen tehtävät hoitaa ryhmälähetys.
Liitännällä on aina useita osoitteita: linkkipaikallinen, yksi tai
useampi maailmanlaajuinen ja usein yksityisyyttä suojaavia väliaikaisia
osoitteita. Aliverkko on lähes aina `/64`: 64 bittiä verkolle ja 64
liitännän tunnisteelle. Operaattori antaa kotiin tyypillisesti `/56`-
tai `/48`-lohkon, eli 256 tai 65 536 aliverkkoa.

IPv6:n (NDP ja *Packet Too Big*), toisin kuin IPv4:ssä usein luullaan.

## Komennot

Samat `ip`-komennot toimivat IPv6:lle valitsimella `-6`. Kaikissa
ympäristöissä, joissa tämän tutoriaalin esimerkit ajetaan, ytimen
IPv6-tuki ei ole käytössä, joten seuraavat komennot ovat testaamattomia
esimerkkejä:

```text
ip -6 addr add 2001:db8:10:20::10/64 dev eth0
ip -6 route add default via fe80::1 dev eth0   # linkkipaikallinen reititin
ip -6 neigh                                    # NDP-naapuritaulu
ping -6 -c 1 2001:db8:10:20::1
ping -c 1 fe80::1%eth0                         # liitäntä on pakko kertoa
ss -6 -tln
```

Linkkipaikallinen osoite on yksikäsitteinen vain liitännän sisällä,
joten se tarvitsee *vyöhykkeen* (`%eth0`). URL-osoitteissa IPv6-osoite
kirjoitetaan hakasulkeisiin: `http://[2001:db8::1]:8080/`.

## Käytännössä

- **Älä oleta IPv4:ää.** Käytä nimen selvittämiseen funktiota
  `getaddrinfo` (Pythonissa `socket.create_connection`), joka palauttaa
  kummankin perheen osoitteet. Älä tallenna osoitteita 32-bittisiin
  kenttiin äläkä jäsennä niitä pisteiden perusteella.
- **Happy Eyeballs** (RFC 8305): kun nimellä on sekä IPv6- että
  IPv4-osoite, asiakas yrittää molempia lomittain eikä jää odottamaan
  toimimatonta IPv6-reittiä. Selaimet ja `curl` tekevät näin.
- **Palomuuri koskee kumpaakin protokollaa.** Kaksipinoisessa verkossa
  IPv4:n säännöt eivät suojaa IPv6:ta. Unohdettu IPv6-palomuuri on
  yleinen aukko.
- **Päästä läpi tarvittava ICMPv6** (NDP, *Packet Too Big*); muuten
  yhteydet katkeavat oudosti suurilla paketeilla.
